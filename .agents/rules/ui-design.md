# UIデザイン

UI を変更する前に `.agents/DESIGN.md` を読む。
機能・UX 要件は `docs/10_プロダクト設計/画面設計.md`、ビジュアル表現は `DESIGN.md` を正本とする。

## 必須ルール

- 画面と通常セクションは、一枚のキャンバスとして同じ背景で扱う
- 通常の面に背景、外枠、角丸、影を一律付与しない
- 情報の階層は、余白、数値の大きさ、配置、罫線の順に表現する
- 一覧・セット記録は表または行として表現し、安易にカード化しない
- 通常領域の角丸は原則 `0` とする
- ボタン、入力欄、選択コントロールの角丸は `radius.sm`（6px）から `radius.md`（10px）に留める
- 影はモーダル、ドロワー、固定タイマーバナーなど、前面へ浮く要素に限定する
- 入力欄と表ヘッダーには、識別に必要な淡い補助背景を使用できる
- 色値・余白・フォントサイズは、モバイルは `styles/theme.ts`、web は `styles.css` の
  CSS カスタムプロパティから参照する。直書きしない
- 1画面で最も大きい数値は1つに絞る
- 0 と未記録を同じ見た目にしない。未記録は `—` で示す
- web は全ブレークポイントで横スクロールを発生させない

## 許可する例外

- 比較対象となるサマリー数値の細い外枠
- 状態を示すステータスバッジのピル形状
- 操作要素として必要なボタンと入力欄の小さな角丸
- モーダル、ドロワー、メニューなどオーバーレイの背景と影
- エラー、警告、選択中を伝える意味のある状態色

例外を使う場合も、同じ要素へ背景・枠線・角丸・影をすべて重ねない。

## 禁止事項

- セクションごとに同じ見た目のカードを量産する
- カードの内側へ同じ見た目のカードを入れ子にする
- 見た目を整える目的だけで角丸や影を追加する
- 同じ階層のすべての要素を均一なカードグリッドへ変換する
- テーマ定数を経由せず色・余白・サイズを直書きする
- web で PC 用テーブルをスマートフォンから横スクロールさせる
- `overflow: hidden` を安易に祖先要素へ指定し、固定表示を壊す
- フォーカス表示、エラー表示、選択状態を装飾削減と一緒に消す
- 空状態を「データがありません」だけで終わらせる

## 実装前チェック

1. 既存のテーマ定数と共通コンポーネントで対応できるか確認する
2. 変更する要素が閲覧情報、操作要素、オーバーレイのどれかを判定する
3. 外枠ではなく余白や罫線で表現できるか検討する
4. モバイルと管理画面の両方に同じ情報があるなら、表現を揃える

## 実装後チェック

- カードの入れ子が増えていない
- 通常コンテンツに新しい影が増えていない
- 意味のない角丸が増えていない
- テーマ定数を経由しない色・余白・サイズが増えていない
- 1画面で最も大きい数値が1つに保たれている
- フォーカス、選択状態、エラー状態を識別できる
- web は 1440px / 1024px / 768px / 390px で `scrollWidth` が `clientWidth` を超えていない
- `npm --prefix apps/web run build` が成功する
