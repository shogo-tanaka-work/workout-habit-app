# 認証

ゴール像と未確定事項は `.agents/memory/auth-model.md` を読む。**現状は単一 Bearer トークンのみ**。

## 現状の実装

- `apps/api/src/index.ts` のミドルウェアが `/health` 以外の全リクエストで
  `Authorization: Bearer <API_TOKEN>` を検証する
- ユーザーの概念はまだ無い。D1 のどのテーブルにも `user_id` がない
- モバイルはトークンを `app_settings` に、管理画面は `localStorage` に保存している

## 変更時に守る不変条件

方式が変わっても以下は崩さない。

- 設定不足（Secret 未設定、JWKS 取得失敗）のときは **fail closed**。認証をスキップするフォールバックを書かない
- 認証を要しないパスは明示的な許可リストにする。「特定パスだけ弾く」形にしない
- ローカル開発で検証を省略する場合、localhost 系のホスト名に限定する
- トークン比較は Web Crypto による固定時間比較を使う
- 認証済みユーザーはリクエストコンテキストで持ち回る。モジュールスコープへ置かない
- 認証失敗は `401` を返し、理由を詳細に漏らさない（「どのチェックで落ちたか」をレスポンスに書かない）
- トークン・メールアドレス・`sub` をログへ出さない

## マルチユーザー化で必要になること（Step 4）

要件定義を終えてから着手する。実装に入る前にこのファイルを更新する。

- ブラウザ経路: Cloudflare Access JWT の署名・issuer（team domain）・AUD を Worker 側で**再検証**する。
  Access を通っている前提でヘッダを信用しない
- モバイル経路: Google ID トークンを Google の JWKS で検証し、`aud` / `iss` / 有効期限を確認する
- どちらの経路も、検証結果から同じ「ユーザー ID + ロール」を解決する。
  その先のロジックは経路を意識しない
- `/backup` と `/analytics/*` は認証済みユーザー自身のデータだけを対象にする（`admin` を除く）
- `/backup` の全置換をユーザースコープの置換に変える。**他人のデータを消せる経路を残さない**
- ロールは `admin` と `member` の2つ。ロール判定を各 route に散らさず1か所に集約する
