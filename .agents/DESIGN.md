# デザイン原則

本プロダクトのビジュアルデザインに関する**正本**とする。色・余白・文字サイズ・角丸・影・
レイアウトの決まりは、すべてこのファイルに集約する。`rules/` 側には同じ内容を書かない。

`docs/10_プロダクト設計/画面設計.md` は機能・画面構成・UX 要件の設計書として扱う。
角丸、背景、枠線、影などの視覚表現が競合する場合は、このファイルを優先する。

## 目指すトーン

- ジムで片手・短時間で操作できる、視認性優先の暖色ダーク UI
- 装飾ではなく、数値の大きさ、余白、罫線で情報の階層を伝える
- 画面を一枚のキャンバスとして見せる
- 記録中（操作）と振り返り（閲覧）を明確に分ける
- モバイルと管理画面で、色・語彙・数値の表現を揃える

## 共通トークン

| 用途 | 値 |
|---|---|
| 背景 | `#171411` |
| 面（わずかに持ち上げる） | `#1e1a16` / `#27221c` |
| 罫線 | `#393229` / `#4d4437` |
| 文字 | `#ece4d8`（主） / `#a89d8d`（副） / `#7b7163`（微） |
| アクセント | `#df8a3d`、文字上では `#f0b375` |
| アクセント面 | `#332617` / `#6b4a25` |
| アクセント面の上の文字 | `#1f1408` |
| 危険 | `#e0705f`、面は `#2e1b18` |
| グラフ | 第1系列 `#df8a3d` / 第2系列 `#6f9fd8` |
| 余白 | `2` / `4` / `8` / `12` / `16` / `24` / `48` |
| 文字サイズ | `12` / `15` / `17` / `20` / `24` / `30` |
| 角丸 | `6`（操作要素） / `10`（オーバーレイ） |

中間値を作らない。`2` はラベルと値のような密着させたい組み合わせにだけ、
`30`（display）は1画面で1つだけ使う主役の数値にだけ使う。

文字サイズは一般的なアプリより一段大きい。**ジムで、腕を伸ばした距離から、
汗をかいた状態で読む**ことを前提にしているため。小さくして詰め込みたくなったら、
サイズではなく情報量のほうを減らす。web も同じ値を使い、2アプリで表現を揃える。

実装は次の2ファイルが正本で、**同じ値を保つ**。

- `apps/mobile/src/styles/theme.ts` の `colors` / `spacing` / `fontSize` / `radius`
- `apps/web/src/styles.css` の `:root` カスタムプロパティ（`--space-*` / `--font-*` / `--radius-*`）

**web だけが持つ値**: `--accent-mid: #b06f2e`。ヒートマップ（`.heatmap-level-2`）の
4段階を作るための中間色で、モバイルにヒートマップが無いため対応する定数を置いていない。
片側にしかない値を増やすときは、ここに理由を書く。

## レイアウト原則

### 一枚のキャンバス

- 画面全体、主要セクションは同じ背景色を使う
- セクションごとに背景・外枠・影を重ねない
- web は最大幅 880px、左右余白で読みやすさを確保する

### 情報の区切り

優先順位は次のとおり。上位で区別できる場合、下位の装飾を追加しない。

1. 余白
2. 数値の大きさとウェイト
3. 配置とカラム
4. ヘアライン罫線
5. 淡い背景色
6. 枠線
7. 影

### 角丸

- 通常の領域、表、リスト、カラムは角丸を使わない
- ボタン、入力欄、選択コントロール、モーダルは 6px または 10px（`radius.sm` / `radius.md`）に限る
- ステータスバッジのピル形状は、短い状態表示に限って許可する
- **円・ドット・進捗バーの半径は定数を通さなくてよい**。部位ドット（4px）、
  グラバー（2px）、FAB（28px）のように、形そのものを決める値は `radius` の段階では表せない

### 影

- 通常コンテンツに影を使わない
- **現在、影を使っているのは `appStyles.fab`（ホーム右下の記録開始ボタン）だけ。**
  スクロールするカレンダーの上を横切って留まる要素で、面が重なっていることを示す必要があるため
- モーダル・ドロワー・固定バナーは「浮く要素」だが、暖色ダーク地では罫線と面色で
  十分に前後が分かるため影を付けていない。増やすときはこの節に理由を追記する

## コンポーネント別ルール

### 数値表示

このアプリの主役は数値（重量・レップ・ボリューム・推定1RM）。

- 区画の指標は `apps/mobile/src/components/StatSummary.tsx` を使う。
  **主役の数値を1つだけ大きく（`fontSize.xl` = 24px）見せ、残りは1行の従属指標として並べる**
- 1画面で最も大きい数値は1つに絞る。同じサイズの数値を並べて主役を消さない
- 単位は数値より小さく、副文字色にする。値と単位は別の要素として描画する
- 単位は「回」「kg」のような計測単位のときだけ付ける。
  「セット」のようにラベルが数える対象そのものを表す場合は、ラベルだけにして単位を重ねない
- 数値のフォーマットは `utils/number.ts`（mobile / web それぞれ）の
  `formatCount` / `formatVolume` / `formatWeight` を通す。各所で `toLocaleString` や `toFixed` を書かない
- 同じ値の表記を2アプリで揃える（ボリュームは両方 `12,340kg`）
- 0 と未記録を同じ見た目にしない。未記録は `—` で示す

**このスケールを変えるときは、数値を直書きしている箇所を必ず洗う。**
ここの「24px」のような具体値がドキュメントに散っていると、片方だけ古くなる。

### 一覧・表組み

- 一覧全体をカードで囲わない
- 表ヘッダーには淡い背景色（`surface`）を使用できる
- 行はヘアラインで区切る
- セット記録は表として表現する。行ごとにカード化しない

### フォーム・入力

- 入力欄は周囲と識別できる淡い背景色を使う
- フォーカス時はアクセント色の境界線を表示する
- 入力グループ全体をカード化しない
- **指で押す選択肢は `choiceChip`（高さ44pt・幅72pt以上・文字17px）を使う。**
  `pill`（文字12px・高さ約28pt）は、押す対象ではない状態表示か、
  1行に3つ以上並べる必要がある補助操作にだけ残す
- 数値入力のステッパーは 44pt 四方を確保する

### カテゴリ色（部位）

系列色（アクセント＋第2系列の2色）とは別の用途として、**部位の識別色**だけを認める。
量の大小や良し悪しを表さず、「胸か、背中か、脚か」を色相だけで見分けるために使う。

- 正本は `apps/mobile/src/styles/theme.ts` の `bodyPartColors`。取得は `bodyPartColor()` を通す
- 用途はカレンダーの日別マーク、種目行の先頭ドット、部位を選ぶチップのドットに限る。
  面や文字の塗りには使わない
- 未分類は `unknownBodyPartColor`（微文字色）にして、色で意味を主張させない
- 色だけに情報を持たせない。カレンダーのマークは色＋種目数、種目行は色＋種目名で読める
- 部位を増やすときは、暖色ダーク地の上で隣接色と識別できるまで彩度を落としてから追加する

### グラフ

- 外部チャートライブラリは未導入。mobile は `components/TrendChart.tsx`、
  web は `components/{LineChart,BarChart,CalendarHeatmap}.tsx` の自作 SVG を使う
- 系列色はアクセントと第2系列の2色まで。3系列以上が必要になったら情報設計を疑う
- グリッド線はヘアラインより濃くしない
- 軸ラベルはグラフ領域を圧迫しない位置に置く
- **縦軸は 0 を基準にしない。** 実際の値域に合わせて下限を持ち上げる。
  90〜100kg の推移を 0〜100kg で描くと、伸びているかどうかが読めない一直線になる。
  目盛りは切りのよい刻みへ丸め、刻みが整数でないときはラベルにも小数を出す
  （線が指す値と読めた値をずらさないため）

### 空状態

- 「データがありません」だけで終わらせない。次にとる行動を1文で示す
- 同じ意味の空状態は同じ文言にする（「〜はまだありません。」＋行動の1文）
- 空状態のためにイラストやアイコンを追加しない

## 許可する例外

- 比較対象となるサマリー数値の細い外枠
- 状態を示すステータスバッジのピル形状
- 操作要素として必要なボタンと入力欄の小さな角丸
- モーダル、ドロワー、メニューなどオーバーレイの背景
- エラー、警告、選択中を伝える意味のある状態色

例外を使う場合も、同じ要素へ背景・枠線・角丸・影をすべて重ねない。

## 禁止事項

- セクションごとに同じ見た目のカードを量産する
- カードの内側へ同じ見た目のカードを入れ子にする
- 見た目を整える目的だけで角丸や影を追加する
- 異なる意味の情報を、均一なカードグリッドへ並べる
- テーマ定数を経由せず色・余白・フォントサイズを直書きする
- web で PC 用テーブルをスマートフォンから横スクロールさせる
- `overflow: hidden` を安易に祖先要素へ指定し、固定表示を壊す
- フォーカス表示、エラー表示、選択状態を装飾削減と一緒に消す

## 実装前チェック

1. 既存のテーマ定数・共通スタイル・共通コンポーネントで対応できるか確認する
2. 変更する要素が閲覧情報、操作要素、オーバーレイのどれかを判定する
3. 外枠ではなく余白や罫線で表現できるか検討する
4. モバイルと管理画面の両方に同じ情報があるなら、表現を揃える

## 実装後チェック

- カードの入れ子が増えていない
- 通常コンテンツに新しい影が増えていない
- 意味のない角丸が増えていない
- テーマ定数を経由しない色・余白・サイズが増えていない
- 1画面で最も大きい数値が1つに保たれている
- キーボード / タップフォーカス、選択状態、エラー状態を識別できる
- 押す対象が 44pt 四方を確保できている
- web は 1440px / 1024px / 768px / 390px で横スクロールが発生しない
- `npm --prefix apps/web run build` が成功する
